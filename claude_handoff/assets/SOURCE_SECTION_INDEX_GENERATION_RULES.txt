SOURCE_SECTION_INDEX.txt generation rules

Input
- report.txt generated by the Streamlit app.

Output
- A plain text index that lists each report section in order with line numbers.

Parsing rules
1. Split report.txt into lines.
2. Treat a line of repeated hyphens as a section boundary.
3. A section title is usually the first non-empty line after a boundary.
4. Keep divider sections such as PERFORMANCE, GOOGLE TRENDS, AUCTION INSIGHTS, and RECOMMENDATIONS.
5. Number every section in source order.
6. Record the 1-based line number where each section title starts.
7. Extract the client/market from the first report title line.
8. Extract the period from the first line matching a quarter/date pattern such as "Q2 2026 (Apr - Jun 2026)".

Important disambiguation
- "Other Summary" in the PERFORMANCE block is channel/campaign-type Other.
- "Other Summary + YoY" in the destination block is destination Other.
- "Other (Destination) Top 10 campaigns" is an optional destination Other supporting section generated when Google/MS campaign exports are uploaded.
- The handoff must explicitly warn Claude not to use Performance Other data for destination Other slides.

Validation checks
- The generated index should not fail if a future report has an extra section.
- If expected sections are missing, write a "Missing expected sections" note in SOURCE_SECTION_INDEX.txt and PACKAGE_MANIFEST.json.
- If extra sections are present, list them; do not silently discard them.
