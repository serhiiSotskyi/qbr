SOURCE_SECTION_INDEX.txt generation rules

Input
- report.txt generated by the Streamlit app.

Output
- A plain text index that lists each report section in order with line numbers.

Parsing rules
1. Split report.txt into lines.
2. Treat bracket headings like [Cover], [Agenda], [All Performance Summary] as section starts.
3. Number every section in source order.
4. Record the 1-based line number where each section heading starts.
5. Extract the period from the first Subtitle line matching a quarter/date pattern such as "Q2 2026 (Apr - Jun 2026)".
6. Record Streamlit slide numbers where present.

Expected common section order for the current Wightlink QBR
01. [Cover]
02. [Agenda]
03. [Trends]
04. [Trends - ...]
05. [Trends - ...]
06. [Trends - ...]
07. [Auction Insights - Generic]
08. [Auction Insights - Brand]
09. [Performance]
10. [All Performance Summary]
11. [All Performance YoY Trend]
12. [Brand Performance Summary]
13. [Brand Performance YoY Trend]
14. [Generics Performance Summary]
15. [Generics Performance YoY Trend]
16. [PMax Performance Summary]
17. [PMax Performance YoY Trend]
18. [Closing]

Validation checks
- If expected sections are missing, write a "Missing expected sections" note in SOURCE_SECTION_INDEX.txt and PACKAGE_MANIFEST.json.
- If extra sections are present, list them; do not silently discard them.
- If Trend section titles are raw filenames, add a note instructing Claude to use CSV header query names.
